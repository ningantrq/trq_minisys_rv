## 外设架构概述

在完成CPU核心后，我们需要为CPU添加外设支持，使其能够与外部世界交互。本设计采用**内存映射I/O（Memory-Mapped I/O, MMIO）**架构，所有外设通过统一的内存地址空间访问。

### **三层架构**

```
┌─────────────────────────────────────────────────────────────┐
│                      SOC 顶层模块                            │
│                   (minisys_soc.v)                           │
│  ┌──────────────────┐         ┌──────────────────┐         │
│  │   CPU Core       │◄───────►│  Periph Bridge   │         │
│  │ (minisys_core.v) │ dram接口│(periph_bridge.v) │         │
│  └──────────────────┘         └────────┬─────────┘         │
│                                        │                    │
│         ┌──────────────────────────────┼───────────┐       │
│         │              │               │           │       │
│         ▼              ▼               ▼           ▼       │
│    ┌────────┐    ┌────────┐      ┌────────┐  ┌────────┐  │
│    │ UART   │    │ Timer  │  ... │  LED   │  │ Switch │  │
│    └────────┘    └────────┘      └────────┘  └────────┘  │
└─────────────────────────────────────────────────────────────┘
```

## 内存地址映射

### **地址空间划分**

所有外设都被映射到特定的内存地址范围：

```verilog
`define MEM_UART_ADDR       32'h00000000  // UART基地址
`define MEM_TIMER_ADDR      32'h10000000  // Timer基地址
`define MEM_VRAM_ADDR       32'h20000000  // 显存基地址
`define MEM_LED_ADDR        32'h30000000  // LED基地址
`define MEM_SWITCH_ADDR     32'h40000000  // Switch基地址
`define MEM_KEYBOARD_ADDR   32'h50000000  // 键盘基地址
`define MEM_SEG_ADDR        32'h60000000  // 数码管基地址
`define MEM_PWM_ADDR        32'h70000000  // PWM控制器基地址
`define MEM_RAM_ADDR        32'h80000000  // RAM基地址
`define MEM_WATCHDOG_ADDR   32'h90000000  // 看门狗基地址
```

### **完整地址映射表**

| 地址范围 | 外设 | 类型 | 功能 |
|---------|------|------|------|
| `0x0000_0000 - 0x0000_0003` | **UART** | 串口通信 | 收发数据、状态查询 |
| `0x1000_0000 - 0x1000_0014` | **Timer** | 定时器 | 周期计数、定时中断 |
| `0x2000_0000 - 0x2FFF_FFFF` | **VRAM** | 显存 | VGA显示缓冲 |
| `0x3000_0000 - 0x3000_0017` | **LED** | 输出 | 24个LED控制 |
| `0x4000_0000 - 0x4000_0017` | **Switch** | 输入 | 24个拨码开关 |
| `0x5000_0000 - 0x5000_0003` | **Keyboard** | 输入 | 4x4矩阵键盘输入 |
| `0x6000_0000 - 0x6000_0003` | **Segment Display** | 输出 | 8位数码管显示 |
| `0x7000_0000 - 0x7000_001B` | **PWM Controller** | 输出 | 4通道PWM信号生成 |
| `0x8000_0000 - 0xFFFF_FFFF` | **RAM** | 数据存储 | 程序和数据内存 |
| `0x9000_0000 - 0x9000_000F` | **Watchdog** | 控制 | 系统监控和复位 |

## 🎯 设计理念

### **1. 统一接口**

所有外设访问都通过标准的Load/Store指令：

```c
// C代码示例
#define LED_BASE 0x30000000
#define UART_TX  0x00000000

// 点亮LED 0
*(volatile uint32_t*)(LED_BASE + 0) = 1;

// 发送字符
*(volatile uint32_t*)UART_TX = 'H';
```

转换为汇编：

```assembly
# 点亮LED 0
li   t0, 0x30000000    # LED基地址
li   t1, 1             # 状态: ON
sw   t1, 0(t0)         # 写入LED寄存器

# 发送字符
li   t0, 0x00000000    # UART TX地址
li   t1, 'H'           # 字符
sw   t1, 0(t0)         # 写入UART
```

### **2. 地址译码策略**

```verilog
// Bridge根据地址高位选择外设
case (dram_addr_i & 32'hF0000000)
    32'h00000000: // UART
    32'h10000000: // Timer
    32'h20000000: // VRAM
    32'h30000000: // LED
    32'h40000000: // Switch
    32'h80000000: // RAM
endcase
```

### **3. 时序协调**

不同外设有不同的响应时间：

| 外设 | 延迟 | 原因 |
|------|------|------|
| LED | 1周期 | 寄存器访问 |
| Switch | 1周期 | 组合逻辑 |
| Timer | 1周期 | 寄存器访问 |
| UART | 1周期（启动）+ N周期（传输） | 串行通信 |
| RAM | 6周期 | 8位宽BRAM |
| VRAM | 6周期 | 类似RAM |

## 🔌 外设类型

### **输入型外设**

**特点**：CPU从外设读取数据

- **Switch（拨码开关）**：读取24个开关状态
- **UART RX（串口接收）**：接收外部数据
- **Timer（定时器）**：读取时间计数

**实现要点**：
- 组合逻辑或简单寄存器
- 数据随时可读
- 无写入操作（只读）

### **输出型外设**

**特点**：CPU向外设写入数据

- **LED（灯）**：控制24个LED开关
- **UART TX（串口发送）**：发送数据到外部
- **VRAM（显存）**：写入显示数据

**实现要点**：
- 寄存器保持状态
- 写入立即生效或进入队列
- 可能需要状态标志（忙/空闲）

### **双向外设**

**特点**：可读可写

- **Timer（定时器）**：读计数值，写比较值
- **RAM（内存）**：读写数据


## Bridge

**外设桥接器（Peripheral Bridge）**是CPU和所有外设之间的"路由器"和"协调员"，负责将CPU的访存请求路由到正确的外设，并协调不同外设的时序差异。

### **核心职责**

1. **地址译码**：根据访存地址判断目标外设
2. **请求路由**：将读写请求转发给正确的外设
3. **数据收集**：汇总各个外设的响应数据
4. **时序协调**：处理不同外设的响应延迟
5. **状态管理**：维护外设相关的寄存器和标志


## LED
CPU控制24个LED的开关状态
控制24个LED，分为3组：
- 绿色LED（0-7）：8个
- 黄色LED（8-15）：8个
- 红色LED（16-23）：8个

每个LED独立控制，支持读回当前状态。

## Switch
CPU读取24个拨码开关的状态
读取24个拨码开关的状态：
- 每个开关独立
- 实时反映物理开关位置
- 只读，不可写


## UART

UART（Universal Asynchronous Receiver/Transmitter，通用异步收发器）是最常用的串行通信协议，用于CPU与外部设备（如PC、传感器等）进行数据交换。

### **关键特性**

- **异步通信**：无需时钟同步，只需约定波特率
- **全双工**：可以同时发送和接收数据
- **简单可靠**：硬件实现简单，广泛应用
- **标准协议**：符合RS-232标准

### **数据帧格式**

```
┌─────┬────┬────┬────┬────┬────┬────┬────┬────┬────┬──────┬─────┐
│Start│ D0 │ D1 │ D2 │ D3 │ D4 │ D5 │ D6 │ D7 │ Stop │Idle │
│ Bit │    │    │    │    │    │    │    │    │ Bit  │     │
└─────┴────┴────┴────┴────┴────┴────┴────┴────┴────┴────┴────┴──────┴─────┘
  0     LSB                                MSB    1      1

时序:
- Idle: 空闲状态，线路保持高电平
- Start Bit: 起始位，拉低电平
- Data Bits: 8位数据，LSB先发送
- Stop Bit: 停止位，拉高电平
- Idle: 回到空闲状态
```

## Timer

定时器（Timer）是处理器系统中的关键外设，提供精确的时间测量和定时中断功能。
### **核心功能**
1. **Cycle计数器**：记录自启动以来的时钟周期数（64位）
2. **Time计数器**：记录实时时间（64位）
3. **比较器**：支持定时中断功能
4. **中断生成**：当Time >= Timecmp时产生中断

### **标准CSR寄存器**

RISC-V定义了以下标准计数器：

| CSR地址 | 名称 | 权限 | 功能 |
|--------|------|------|------|
| 0xC00 | `cycle` | RO | 周期计数低32位 |
| 0xC80 | `cycleh` | RO | 周期计数高32位 |
| 0xC01 | `time` | RO | 时间计数低32位 |
| 0xC81 | `timeh` | RO | 时间计数高32位 |
| - | `timecmp` | RW | 比较值低32位（非标准） |
| - | `timecmph` | RW | 比较值高32位（非标准） |

## RAM

**数据RAM（Data RAM）**是CPU的主存储器，提供指令存储和数据存储功能。采用双端口BRAM实现，支持独立的指令读取和数据读写操作。

### **核心特性**

- ✅ **双端口访问**：端口A用于指令读取，端口B用于数据读写
- ✅ **字节寻址**：支持8位字节访问
- ✅ **多周期访问**：32位数据需要4个字节周期（6周期总延迟）
- ✅ **写掩码支持**：支持字节、半字、字的部分写入

### **指令读取时序（6周期）**

```
周期    0     1     2     3     4     5     6
        │     │     │     │     │     │     │
enable ─┐                                   ┌─
        └───────────────────────────────────┘
        
状态   IDLE  B_00  B_01  B_10  B_11  DONE  IDLE
        
地址   Addr  +1    +2    +3    +3    +3    -
        
BRAM读       [延迟]Byte0 Byte1 Byte2 Byte3
        
数据组装                [7:0] [15:8][23:16][31:24]

        ──────────────────────────────┘   └──
```

### **数据写入时序（6周期）**

```

        │     │     │     │     │     │     │
enable ─┐                                   ┌─
        └───────────────────────────────────┘
```

## VRAM
**视频RAM（Video RAM, VRAM）**是专门用于VGA显示的双端口存储器，支持CPU写入像素数据和VGA控制器读取显示数据的并行操作。

### **核心特性**

- **双端口架构**：端口A供CPU读写，端口B供VGA控制器读取
- **异步时钟域**：CPU时钟和VGA时钟独立运行
- **降低分辨率**：实现320x240分辨率（640x480的1/4）
- **6周期访问**：CPU访问32位数据需要6个周期
- **写掩码支持**：支持字节级写入控制


## VGA
VGA（Video Graphics Array）是标准的视频显示接口，本设计实现640x480@60Hz分辨率的彩色显示系统，包括：
- **VRAM（显存）**：存储显示数据
- **VGA控制器**：生成时序信号
- **双端口访问**：CPU写入，VGA读取

## Display
**显示控制器（Display Controller）**是VGA显示系统的顶层封装模块，集成了VGA控制器和显存（VRAM），为系统提供完整的图形显示功能。

### **核心特性**

- ✅ **独立显示系统**：不依赖CPU直接驱动VGA显示
- ✅ **集成VRAM**：内置IP核实现的双端口显存
- ✅ **自动刷新**：持续扫描显存并输出到VGA接口
- ✅ **只读显存**：从CPU角度看，此模块的VRAM是只读的（显示预设内容）





## PWM Controller

PWM（脉冲宽度调制）控制器是一种常用的输出设备，用于生成具有特定占空比和周期的方波信号，广泛应用于电机控制、灯光调节、音频输出等领域。本设计实现了4通道独立可控的PWM控制器。

### **核心特性**

- ✅ **4通道独立输出**：每个通道可独立配置和控制
- ✅ **可编程周期**：支持灵活的周期设置（32位寄存器）
- ✅ **可编程占空比**：每个通道独立设置占空比（32位寄存器）
- ✅ **全局/通道使能控制**：支持整体和单个通道的开启/关闭
- ✅ **状态反馈**：提供各通道就绪状态指示

### **寄存器定义**

| 地址偏移 | 名称 | 权限 | 功能 | 复位值 |
|---------|------|------|------|------|
| `0x00` | `period_reg` | RW | 周期寄存器（全局） | `0x000003E8` (1000)
| `0x04` | `duty0_reg` | RW | 通道0占空比寄存器 | `0x000001F4` (500)
| `0x08` | `duty1_reg` | RW | 通道1占空比寄存器 | `0x000001F4` (500)
| `0x0C` | `duty2_reg` | RW | 通道2占空比寄存器 | `0x000001F4` (500)
| `0x10` | `duty3_reg` | RW | 通道3占空比寄存器 | `0x000001F4` (500)
| `0x14` | `control_reg` | RW | 控制寄存器 | `0x00000000`
| `0x18` | `status_reg` | RO | 状态寄存器 | `0x00000001`

### **控制寄存器位定义**

| 位 | 名称 | 功能 |
|----|------|------|
| 0 | `ENABLE_BIT` | 全局PWM使能（0:禁用，1:使能）
| 1 | `CH0_ENABLE_BIT` | 通道0使能（0:禁用，1:使能）
| 2 | `CH1_ENABLE_BIT` | 通道1使能（0:禁用，1:使能）
| 3 | `CH2_ENABLE_BIT` | 通道2使能（0:禁用，1:使能）
| 4 | `CH3_ENABLE_BIT` | 通道3使能（0:禁用，1:使能）

### **状态寄存器位定义**

| 位 | 名称 | 功能 |
|----|------|------|
| 0 | `READY_BIT` | 控制器就绪状态（1:就绪）
| 1 | `CH0_READY_BIT` | 通道0就绪状态（1:就绪）
| 2 | `CH1_READY_BIT` | 通道1就绪状态（1:就绪）
| 3 | `CH2_READY_BIT` | 通道2就绪状态（1:就绪）
| 4 | `CH3_READY_BIT` | 通道3就绪状态（1:就绪）

### **工作原理**

PWM信号通过计数器和比较器实现：

1. **周期设置**：`period_reg`寄存器定义一个完整PWM周期的计数值
2. **占空比设置**：`dutyx_reg`寄存器定义高电平持续的计数值
3. **计数逻辑**：当PWM使能时，计数器从0开始递增，达到`period_reg`后重置
4. **输出控制**：当计数值小于`dutyx_reg`时，对应通道输出高电平；否则输出低电平

### **使用示例**

```c
// C代码示例
#define PWM_BASE 0x70000000

// 设置周期为2000（2ms）
*(volatile uint32_t*)(PWM_BASE + 0x00) = 2000;

// 设置通道0占空比为50% (1000/2000)
*(volatile uint32_t*)(PWM_BASE + 0x04) = 1000;

// 设置通道1占空比为25% (500/2000)
*(volatile uint32_t*)(PWM_BASE + 0x08) = 500;

// 使能PWM控制器和所有通道
*(volatile uint32_t*)(PWM_BASE + 0x14) = 0b00011111;
```

## Watchdog Timer

看门狗定时器（Watchdog Timer，WDT）是一种系统监控机制，用于检测和恢复系统故障。当系统程序出现异常导致看门狗未能及时被喂狗时，看门狗会产生中断或复位信号，确保系统能够从故障中恢复。

### **核心特性**

- ✅ **可编程超时时间**：支持灵活的超时设置（1ms精度）
- ✅ **中断支持**：超时可产生中断信号
- ✅ **复位支持**：超时可产生系统复位信号
- ✅ **自动重载功能**：支持循环计时模式
- ✅ **状态反馈**：提供看门狗活动状态和超时指示

### **寄存器定义**

| 地址偏移 | 名称 | 权限 | 功能 | 复位值 |
|---------|------|------|------|------|
| `0x00` | `timeout_reg` | RW | 超时时间寄存器（ms） | `0x0000C350` (50000)
| `0x04` | `control_reg` | RW | 控制寄存器 | `0x00000000`
| `0x08` | `status_reg` | RO | 状态寄存器 | `0x00000000`
| `0x0C` | `reset_reg` | WO | 复位寄存器（写任意值复位计数器） | - |

### **控制寄存器位定义**

| 位 | 名称 | 功能 |
|----|------|------|
| 0 | `ENABLE_BIT` | 看门狗使能（0:禁用，1:使能）
| 1 | `INTERRUPT_EN_BIT` | 中断使能（0:禁用，1:使能）
| 2 | `RESET_EN_BIT` | 复位使能（0:禁用，1:使能）
| 3 | `AUTO_RELOAD_BIT` | 自动重载使能（0:单次，1:循环）

### **状态寄存器位定义**

| 位 | 名称 | 功能 |
|----|------|------|
| 0 | `TIMEOUT_BIT` | 超时状态（1:超时发生）
| 1 | `ACTIVE_BIT` | 活动状态（1:看门狗正在运行）

### **工作原理**

看门狗定时器基于毫秒级计数器实现：

1. **计数逻辑**：以1ms为单位递增计数
2. **超时检测**：当计数值达到`timeout_reg`设定值时，触发超时事件
3. **动作执行**：根据`control_reg`配置，产生中断或复位信号
4. **自动重载**：如果启用，超时后计数器自动重置，继续计时
5. **喂狗操作**：向`reset_reg`写入任意值可重置计数器，防止超时

### **使用示例**

```c
// C代码示例
#define WDT_BASE 0x90000000

// 设置超时时间为10000ms (10秒)
*(volatile uint32_t*)(WDT_BASE + 0x00) = 10000;

// 使能看门狗，启用中断和复位，禁用自动重载
*(volatile uint32_t*)(WDT_BASE + 0x04) = 0b00000111;  // ENABLE | INTERRUPT_EN | RESET_EN

// 喂狗操作（定期执行）
void watchdog_feed() {
    *(volatile uint32_t*)(WDT_BASE + 0x0C) = 0x55AA;  // 写入任意值
}
```

### **注意事项**

1. **喂狗时机**：必须在超时时间内执行喂狗操作，否则会触发中断或复位
2. **中断处理**：如果启用了中断，需要在中断服务程序中清除超时状态
3. **复位影响**：启用复位功能时，超时会导致整个系统复位，需谨慎使用
4. **自动重载**：启用自动重载时，超时后会自动重新开始计时，需注意及时处理
